# 用户记忆与特征总结

打开侧栏“记忆与画像”，选择用户；或在聊天顶部点击同名按钮，直接查看当前聊天。选择会同步到页面地址并在本标签页保留，刷新或切页不再静默回到默认用户。下拉框和实际请求使用同一个用户ID，切换时不会显示上一个用户的旧数据。

页面展示已确认记忆、待确认候选、用户消息数、关系阶段和关系变化。已确认记忆按基本资料、称呼与交流、兴趣偏好、生活习惯等分组，可以删除；历史上被替代的记忆单独折叠。查看记忆不会增加“被对话使用”的计数。

特征总结由配置的模型从该用户的已确认记忆和本人原话生成，展示简短总结、明确自述和本段对话观察。每条均可展开依据，不能把临时聊天行为直接说成稳定人格，不推断敏感属性，也不把角色或其他用户的信息当成这位用户的资料。总结需要来源格式检查和另一次依据核对，有明确问题可修正一次；持续失败时保留原总结并提示失败。

新用户积累三条消息后，成功聊天会安排一次约45秒后的后台总结；有已确认记忆时可更早安排。已有总结后，每积累至少三条新消息再安排更新，同一用户的排队/执行任务合并，避免每轮都调用模型。Worker需正常运行；页面15秒刷新一次，也可点击“生成总结/更新总结”立即整理。

后台原始记忆提取现在包含同用户、同渠道的近期问答上下文，能理解单独回答姓名、年龄等省略句；只从当前用户消息抽取，助手自述和他人经历不能进入用户资料。姓名、年龄、所在地、职业使用各自的键，不互相覆盖。泛化的profile信息不再作为唯一单条资料覆盖其他属性。

删除记忆会清除派生总结，并排除删除前的旧聊天作为之后画像的依据，避免被删信息立刻从旧原话恢复；原始聊天仍保留。清空聊天仍保留已确认长期记忆，但清掉依赖该聊天的派生总结。新的原话和保留的已确认记忆可以继续用于整理。生成期间发生数据变化会拒绝提交过期结果，避免覆盖新的更正。

管理接口均需管理员Cookie或Bearer令牌：

- `GET /api/memory/overview?user_id=...`：分类记忆、候选、画像及依据、统计和关系变化。
- `POST /api/memory/portrait`，正文`{user_id}`：立即生成/更新画像。
- 既有`/api/memories`、`/api/memories/delete`和`/api/memory/candidates/review`继续管理真实记忆。

数据库schema 11增加`user_portraits`缓存表。观察型总结不会自动变成已确认长期事实；聊天仍使用审核后的真实记忆和对话记录。来源删除/更正后旧画像隐藏，有新对话时标记待更新。没有模型或没有可用材料时不生成固定假总结。

旧聊天可通过 `npm run memory:rebuild -- --user=用户ID` 补整理最近40条用户原话。该命令仅重置指定用户这些消息的提取记录，不删除聊天；重新提取、审核该用户的候选并更新总结，调用实际模型。操作前应保持备份并避免另一个提取Worker同时处理同批消息。

验证：`npm run test:portrait`使用隔离数据库和真实模型检查短句姓名/年龄、角色与用户分离、两用户隔离、依据核对、Worker自动更新及删除后不复活。结果在`data/user-portrait-quality-latest.json`。单元测试还包含鉴权、模型失败保留旧结果、生成期间更正、无材料、无密钥和删除时外键完整性。
