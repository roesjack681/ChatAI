# 测试

`npm test` 覆盖：记忆隔离、明确偏好、世界账本不可被对话改写、免打扰、旁白守卫、管理员会话、集成令牌权限边界、角色成长证据、日程幂等与冲突、世界状态流转、外部事件隐私、Worker 失效租约恢复和旧数据库迁移。

自然对话硬检查还会拒绝典型客服套话，以及向用户泄露 Prompt、数据库、系统提示或生活账本等内部机制的回复。

发布前执行：

```powershell
npm run typecheck
npm test
npm run build
npm audit --omit=dev
docker compose --env-file .env.example build
```

容器验收应同时启动 Web 与 Worker，确认 `/api/health` 返回 200，并观察 Worker 完成 `daily_plan`、`world_tick`、记忆、主动消息、Outbox 和承诺任务。

离线模式不调用 DeepSeek。配置密钥后，同一套对话路径会走真实模型。

`npm run test:vision` 在临时数据库中生成一张含编号、红色圆形和蓝色方块的图片，使用当前模型实际验证图文识别、无需重新上传的追问、纯图片消息和图片持久化。模型必须识别出图中的真实编号与颜色；离线套话不算通过。`npm run test:vision -- --fixture-only` 仅生成供浏览器上传测试的 `data/vision-test-fixture.png`，不调用模型。

图片自动测试还覆盖格式伪造、损坏图片、上传大小与数量限制、鉴权、跨用户/渠道隔离、历史图片数量预算、删除级联，以及模型失败后不生成假回复。

`npm run test:knowledge` 用合成的服务列表截图验证角色知识边界：普通分享不变成技术报告，明确询问故障时不装成运维人员，允许按要求读出界面文字；同时检查旧越界回复不会变成专业经历、能复述用户刚解释的词义，以及绘画点评仍可正常进行。使用隔离数据库和真实当前模型。`-- --publish-profile` 仅在测试全部通过后为当前角色发布版本化的 `knowledge_familiar` / `knowledge_unfamiliar` 字段；发布前检查原角色版本未被并发修改。

运行时按角色熟悉领域限制专业推断，图片识别能力仅表示能看到画面，不等于具备画面所属行业的知识。明显的软件运维越界会触发发送前重写，并通过 `hard_checks.role_knowledge_boundary` 和 `knowledge_issues` 记录结果。该检查针对已知问题，不是对所有专业知识边界的完整判定。

真实模型冒烟测试不会在代码或数据库中保存密钥：

```powershell
$env:DEEPSEEK_API_KEY = "你的测试密钥"
npm run test:deepseek
```

测试要求返回提供方为 `deepseek`、回复非空、无动作旁白，并通过身份与系统泄漏硬检查。

`npm run test:conversation` 使用隔离的临时数据库运行真实多轮对话：问候、当前活动、简单接话、用户新经历、知识性问题，以及带旧式工作汇报的历史上下文。它复制公开角色与当日公共日程，不读取私有用户记忆，不在正式聊天列表创建测试会话。必须使用真实 DeepSeek；离线回退不算通过。

`npm run test:conversation -- --publish` 在这些场景全部通过后发布自然对话模块；失败不会发布该候选版本。测试检查的是已知问题（无关工作汇报、连续追问、无依据场景和刻意装熟），不代表已经衡量了所有自然度问题。

对话路径会区分招呼、活动询问、简单接话和实质问题；招呼和简单接话不注入整天的日程、目标与 NPC。发送前发现明确的接话问题时最多重写两次，累计模型用量，并在 `hard_checks.natural_turn_flow`、`dialogue_rewrites`、`dialogue_issues` 中返回结果；服务商失败时不把重写计为成功。

`npm run test:social` 复制当前公开角色、Prompt 和当日公共日程到临时数据库，运行 9 组、45 轮真实对话，覆盖社交试探、个人情况、低能量陪伴、玩笑与界限、称呼记忆，以及活动询问、无聊、表达太模板的反馈。旧式生硬回复和用户报告的插画/灵感对话作为历史夹具，生成和整段评分均能看到这些前文；连续反馈后继续发日常消息，检验是否能自然接回具体话题。逐轮检查模型来源、追问、角色知识和语义复核，再对整段对话的自然度、连贯性、人设一致性、非采访式接话评分；四项均须至少 4/5。评分只用于回归，不代表真人不可辨认。

`npm run test:social -- --case=reported-style` 和 `--case=style-repair` 可复现用户本次报告；`npm run test:social -- --publish` 只有完整九组全部通过才发布候选 Prompt，并为缺少感情状态、相处方式的角色创建新版本，保留已有字段。发布会检查评估期间原角色和 Prompt 未被更改。测试不创建正式聊天、不读取私有用户记忆；最近报告在 `data/social-quality-latest.json`。

活动问题包括省略主语的“在干嘛呢”“这会儿忙啥”。当前活动只读取进行中的角色事件，排除用户私有日程、未来计划和旧职业的默认工作安排；没有活动时依据正在回消息的事实接话。普通闲聊不会整批注入日程、目标和熟人。角色职业改变后，默认插画工作和整理画稿不再自动生成，尚未开始或进行中的过期默认安排取消并写审计；已完成历史保留，人工事件仍可安排绘画。测试覆盖上述边界及连续风格反馈，减少迎宾客套、客服式调整承诺和空泛说教。

文字回复还经过一次模型语义复核，检查无故盘问动机、第三方恋爱劝导、跑题及无依据的角色经历；证据限定为公开角色、已确认事实、当前用户的私有记忆及用户说过的话，旧助手回复不能证明经历。明确问题最多触发两次重写，返回 `semantic_issues`、`semantic_review_status` 和 `hard_checks.contextual_reply`。复核失败标记为 `unavailable`，保留成功草稿，不伪装成检查通过。包含图片上下文时仍由图文生成与知识边界检查处理，不交给纯文字复核。

Flash 首次生成显式关闭思考，语义复核和问题重写启用思考并分配独立预算。复核增加模型调用、延迟与用量，生成、复核和重写的成功调用用量合计进入对话追踪。请求超时、服务商错误、预算耗尽或两次重写后仍有明确接话问题时，不替换成固定聊天回复，返回 502 并保留输入供重试；失败轮次不新增消息、记忆或提醒，也不增加关系互动。

短闲聊的候选生成请求把旧对话作为引用数据提供，保留原话和说话人用于理解，避免旧助手的纯文本输出影响结构化格式，也不把被嫌弃的旧回复继续当作口吻示例；实际历史记录不被改写。明确多余的独立句尾追问可先删除，保留原回答，再做事实与语义复核，返回 `unneeded_followup_removed` 诊断。复核请求遇到临时服务错误或无效 JSON 时最多重试一次，持续失败仍返回 `unavailable`；收到但格式无效的回复用量也会累计。

短闲聊在一次生成请求中产生最多三个不同候选，先过滤明确的接话或知识问题，再由一次复核比较事实、连贯性与语气，选择一条发送；候选都存在问题才重写。`candidate_count` 记录最终一轮的候选数，内部候选和 JSON 不进入聊天历史。图片及实质问题沿用单回复路径。测试覆盖候选解析、无效选择索引、硬检查过滤、只保存所选回复和合计用量。

候选生成和复核启用提供方的 `response_format: { type: "json_object" }`，同时给出 JSON 示例。JSON 模式返回空正文时，在同一超时期限内最多重试一次；持续空正文按模型失败处理。复核本身对传输或解析失败另有一次上限重试；具体协议见 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

`npm run test:contracts` 使用真实 DeepSeek，在隔离数据库复制当前公开角色、Prompt 和当日公共日程，运行 10 组、41 轮回归。覆盖正常游戏话题到约局/加好友的完整链路、原有错误承诺后的连续追问、见面与地址、电话与自拍定位、提醒是否真的设置、代下单及短信、具体歌名书名与名称一致性、用户自己账号的回忆、普通暧昧与文字小游戏。长历史场景在作品偏好后插入 80 条夹具消息再追问，验证完整历史召回。逐轮断言真实模型来源、语义复核、能力检查和明确答案，不以离线回退计为通过。

最近报告保存在 `data/contracts-quality-latest.json`。可用 `--case=legacy-game`、`--case=concrete` 或 `--case=long-recall` 定位单组；单组不能发布。`npm run test:contracts -- --publish` 仅在完整回归通过后发布 `facts` 与 `capability` 模块，保留其他模块和角色档案，并检查评估期间角色及 Prompt 没被改动。此回归验证回答与承诺是否一致，不代表已经达到真人不可辨认。

单元及集成测试还覆盖图片回复的执行承诺检查、候选过滤、没有投递渠道时拒绝确认提醒、有真实已确认记录时读取正确状态，以及历史召回的用户/渠道隔离、删除后不可召回。Webhook 测试只检查配置与数据库状态，不发送外部通知。当前消息的结构化起草包装也只影响模型请求，保存的原始聊天内容保持原样。

`npm run test:reliability` 复制当前公开角色与 Prompt 到隔离数据库，运行 4 组、13 轮真实模型回归：偏好提问不写成新事实、已确认称呼的接续、买相机/搬家/辞职属于用户经历、已确认提醒的状态查询，以及 110 条较新记忆之后对旧偏好的检索。逐轮检查真实提供方、语义复核和能力检查；报告在 `data/reliability-quality-latest.json`，不发布配置，不调用测试 Webhook，不写入正式聊天列表。

存储故障测试通过数据库触发器模拟消息、追踪、候选记忆和投递完成失败，验证事务回滚及可重试。投递测试通过并发调度复现重复发送，检查占用互斥、过期恢复、旧结果不能覆盖新结果和终止失败同步源状态。迁移测试使用缺少投递锁字段的旧 Outbox，验证 schema 9 保留原通知记录。规则记忆测试包含疑问句、转述、假设、作品标题，以及“我喜欢猫，你呢”这种声明与提问混合的消息。

`npm run test:everyday` 使用当前公开角色和 Prompt 的原样副本，在隔离数据库运行 21 组、60 轮日常聊天。包括吐槽与主动求建议的先后切换、分享好消息、目的地纠正、室友/朋友指代、离开与回来、收尾、多个个人问题、日期和时分、宠物名字与称呼跨 80 条消息后的接续、香菜偏好的归属、口语夸张、假设以及恢复提问许可。扩展场景检查反话、旧口味到新口味的变化、朋友的失恋不能变成用户失恋，以及两张合成杯子图片的先后、颜色与“先不用推荐”的要求。跨天/跨周夹具保存原发送时间，验证前天说的“明天考试”和更早说的“下周一考试”不会被错算为当前日期的未来事件。全部实测调用真实模型，未完成不能计为通过；图文沿用图片生成及硬检查路径，不冒充纯文字语义复核已通过。

完整日常回归在 `data/everyday-quality-latest.json` 留存原回复、计划数量及提供方阻断。单组可用 `-- --case=pet-recall`、`--case=relative-date`、`--case=question-permission` 等运行，逗号可选择多组；定向结果保存为 `data/everyday-quality-focused.json`，保留此前的完整报告。情绪与日常接话另作整段检查，有问题时只核实该问题是否能由原话直接证明，并保留初始与复核结论；主观误判不直接改成运行时拦截规则。测试接受“读大学”等语义等价的职业回答，以及中文数字日期；普通问日期不强制多报年份，同月明确上下文允许只说日号，跨月或显式月份冲突仍失败。余额不足或鉴权失败会停止后续批次，不用离线答案补足轮数，不发布 Prompt。

单元测试另覆盖称呼停用与恢复、后台旧称呼候选迟到、重要称呼不被其他记忆挤走、请求少问后又明确允许提问、吐槽不扣关系分及否定/转述不误计好感。模型返回 402 时，聊天应明确报告余额不足并保留输入；不能保存半次聊天或改用固定假回复。

更新后的历史检索测试同时检查旧的“不吃辣”和新的“能吃微辣”能够一起召回、生日等主题词表之外的主体可检索，以及新检索路径仍隔离渠道。图文集成测试模拟模型忽略“先不用推荐”的草稿，要求重写时保留原图片，只保存符合用户要求的最终正文。
