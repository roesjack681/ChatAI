# 双向相处与回复连续性

本次保留已有沉浸身份模块、角色档案、家人朋友、世界设定和私有用户数据，只给语气/相处提示词追加规则，并修改生成与筛选逻辑。

- 正常礼貌请求可以接受，不把普通祈使句都当成冒犯，也不为了显得有个性一律反对。
- 刚遭到直接辱骂时，角色可以表达不喜欢，随后不会立即赔笑、接单。已经说不愿意后，催促不能自动把拒绝改成答应；不把“不愿意”换成“不会、背不好”来搪塞。
- 道歉可以修复语气，普通新话题仍能继续，不强迫用户接受一整套道歉考核，也不持久追究。
- 第三方骂用户、引用他人原话和用户自嘲不作为对角色的攻击。直接辱骂才进入对应用户的关系事件；不会改共享角色设定。
- 轻应声不接成训话。没有具体活动时可以说闲着；追问近况不再连续用“在回你消息”搪塞。换话题后直接接一个具体话题，不只要求用户重新出题。
- 背诗、翻译、短文等内容请求不挤在三个短句候选里，单独生成并给足输出预算；能做和愿不愿意做分开判断。
- 修复了背诗/聊音乐后，询问姐姐、室友、自己或学校名字却继承旧歌名/账号要求的问题。

`packages/prompting/src/agency.ts` 从当前用户最近几轮对话计算本轮相处态度，不新增全局共享的“用户评价”。语义复核同时看到上下文与该态度，选择候选时不再把最热情、最听话自动当成最好。

`npm run test:agency` 在隔离数据库测试6组28轮：用户原话、正常背诗、连续催促、道歉缓和、第三方辱骂倾诉、名字确认。`-- --publish` 仅在整套通过且当前角色/Prompt版本未变化时发布追加后的语气与相处模块。身份模块保持原样。定向运行用 `-- --case=reported,pressure`，另写定向报告，保留完整报告。

`npm run test:social` 的9组45轮回归另检查普通示好、换话题、低情绪、玩笑、称呼记忆及旧式回复后的修复。脚本沿用已发布模块，不再用默认身份覆盖当前身份。

实测记录见 `data/agency-quality-latest.json`、`data/agency-quality-focused.json` 与 `data/social-quality-latest.json`。评分用于回归，不保证之后每一句都完美自然。
