# 架构

目录按 V2.0 方案的职责分区组织。文件名可以和方案示例不同，分区不能混。

```
apps/console     Web 调试台。页面只调用 gateway，不写领域状态。
apps/gateway     统一 HTTP 入口。组织请求，不决定人设。
apps/worker      生活规划、记忆整理、主动消息和投递任务。
packages/core    对话运行时、上下文、社交策略、任务队列、投递。
packages/character
packages/world   daily-life、stories、npc、emotion
packages/people  用户、关系、身份绑定、承诺
packages/memory
packages/proactive
packages/prompting
packages/model   DeepSeek 与离线回退
packages/channels  QQ 与外部事件。渠道不拼接 Prompt。
packages/evaluation
packages/shared
infra/db         SQLite
infra/docker
tests
docs
```

这是模块化单体：Web 和 Worker 共享领域模块与 SQLite 数据卷；QQ 是可选的边缘适配进程，只通过带独立集成令牌的 HTTP 请求调用 Web 网关，不导入领域模块、不挂载数据库。

状态边界：

- 共享世界事实在 `packages/world`。计划不会被模型写成已完成。
- 私人记忆在 `packages/memory`，查询先限定用户。
- 模型在 `packages/model`，没有写账本的入口。
- 沙盒生活事件使用 `sandbox` 环境，和正式时间线分开。
- 角色修改和成长都先生成版本草稿；成长至少需要两个不同日期的证据，核心人格字段禁止自动改写。
- 世界事件保存开始与结束时间，由 Worker 执行 `planned → ongoing → completed`；已有数据库通过 `schema_migrations` 补齐字段。
- 外部应用事件进入待审核区，只能转成所属用户的私有记忆候选或私有日程，不能直接写共享世界。
- Worker 每 30 秒写入心跳；管理台根据心跳新鲜度显示 `running`、`degraded` 或 `offline`。
- Outbox 成功或达到最大重试次数后，会同步关闭对应的主动消息候选与提醒承诺，避免源记录永久停留在 `queued`。
- 每日维护任务清理过期的运行数据：完成任务保留 24 小时、失败任务和 Outbox 保留 30 天、常规任务审计保留 7 天、沙盒事件保留 30 天；用户消息、记忆和正式世界记录不参与自动清理。
- 共享世界设定保存在独立事实库。聊天只读取 `active` 事实；新提案和冲突事实必须审核，接受后旧事实转为 `superseded`，避免单轮模型或外部事件篡改世界观。
- 用户记忆支持稳定键与生命周期。称呼、身份、当前活动等单值记忆发生变化时，旧值转为 `superseded` 并指向新值；检索会记录访问次数与最近使用时间，只有 `active` 记忆进入上下文。
- 用户关系不再按消息数机械增长。系统记录普通互动、积极连接、个人袒露、负面互动和边界声明产生的亲近/信任变化，并计算 `new`、`acquaintance`、`familiar`、`close` 阶段；阶段会进入 Prompt，但不能成为虚构共同经历的依据。
- 系统默认启用全局沉浸模式，所有用户与渠道统一保持林知夏的第一人称角色状态，不主动输出 AI、模型、Prompt、数据库或虚拟角色等技术说明。沉浸表达仍受世界事实和生活账本约束，不能依靠编造过去经历维持真人感。
- 当前发布的角色档案优先决定年龄、职业和城市。编译 Prompt 时忽略重复的旧背景字段；发布角色时同步由系统生成的公开传记事实，旧值保留为 `superseded`，人工维护的事实保留。感情状态和相处方式是可编辑的角色字段。
- 实际操作权限仅限制工具动作，不限制普通玩笑、示好和关系讨论。对话策略区分社交试探、个人情况和明确界限，减少连续反问；短消息的持续互动也能进入相识阶段，无需靠长篇袒露来解除初识语气。
- 文字对话在规则检查后进行有事实依据的语义复核，最多重写两次。原始生成、复核、重写分别配置模型预算，追踪统计成功调用的合计用量；复核不可用会保留诊断状态。
- 生活上下文按提问选择：活动询问只使用进行中的角色事件，日程回顾按明确提问提供当天事件；闲聊、无聊和对口吻的反馈不注入整天安排。目标和熟人仅在相关问题中使用，用户私有日程不能充当角色当前活动。
- 默认插画日程随已发布职业检查适用性。仍保持内置标题、说明和时间的旧默认工作在职业不符时停止生成，并取消当前及未来尚未完成的自动安排、保留审计；管理员独立安排的活动和已完成历史保留。Prompt 同步过滤不适用的旧默认记录，避免 Worker 更新前的短暂不一致。
- 短闲聊一次生成多个候选，经硬检查过滤后，由语义复核比较事实、连贯性和口吻，选择单条回复。内部候选使用结构化输出，只有选中的正文进入聊天与追踪；无效 JSON、无效索引和持续空正文不会当作已检查的回复。图片与实质问题沿用单回复路径。
- `conversation/capabilities.ts` 维护实际能力快照与本轮要求；生成前提供相关限制，候选过滤、语义复核和最终正文再次检查。游戏知识不证明能上号，旧助手说过的承诺不证明有执行能力；追问时纠正旧话，避免用忙、不熟或正在打字拖延。普通社交、明确假设与聊天内的文字游戏不套用外部执行限制。
- `conversation/recall.ts` 在当前用户及渠道内按主题检索完整历史，最多引用 10 条相关原话，包含匹配消息的下一条以保留问答关系；最近 60 条参与本轮要求识别，最近对话窗口仍按原有上限提供。具体作品名称可从更早历史接续；旧回复仅能延续已表达的偏好，不能自行证明经历或实际能力。检索不新增记忆状态，已删除消息不会继续召回。
- 提醒确认、对话能力快照与 Worker 共享目的渠道解析。候选提醒、实际确认、排队和投递完成分开处理；无可投递渠道时确认接口拒绝进入 `pending`。对话查询读取实际提醒状态，未确认时不承诺稍后主动叫醒。当前渠道可投递性依据已启用的 Webhook 配置判断，网络失败仍走现有 Outbox 重试及失败状态。
- 真实模型的候选生成把当前用户消息和起草任务一并作为 JSON 数据传入，旧历史同样作为引用数据提供，减少催促类原话使模型输出纯文本、导致结构化正文为空的问题。原始消息仍用于复核、保存和追踪，离线开发模式保留原始输入路径。
- 聊天的成功消息对、明确记忆、提醒候选、关系变更、追踪及评估在同一事务中提交。追踪或评估写入失败时，不会留下已保存消息却返回发送失败的半次会话；同一用户/渠道的串行等待槽在完成后释放。
- 规则记忆只接受直接陈述，按分句区分声明与相邻问题，排除引用台词、假设和转述。候选审核状态与实际记忆、向量写入同一事务，写入失败仍可重试。检索在当前用户所有有效记忆中排序，不再先按重要程度截断为 100 条。
- 提醒查询与新建请求分开识别，查询不会新增候选，也不会遮蔽已确认记录。确认时间要求有效且带时区的 ISO 日期，统一保存为北京时间；到期查询按实际时刻比较，兼容旧记录中的 UTC 或其他偏移。
- schema 9 为 Outbox 增加投递令牌和占用时间。发送前原子占用 `pending → sending`，并发任务不能同时占用同一条；HTTP 请求超时 10 秒，占用超过 60 秒可恢复，旧令牌的结果不能覆盖新一轮。成功或终止失败与源提醒/主动消息状态在同一事务更新。崩溃后的远端投递结果可能未知，重试沿用相同 `idempotency_key`，接收端仍须按此键去重。
- Worker 在异步模型提取与批量投递期间独立维持 30 秒心跳，重启会更新启动时间。提醒到期入队与 `pending → queued` 也在同一事务中处理，防止并发扫描覆盖新状态。
- 普通聊天也提供当前北京时间和星期；历史引用携带发送时间，用于区分不同日期的“今天、明天”。知道当前时间不证明角色已经吃饭、下课或当地天气，仍需对应事实。语义复核读取同一类时间证据，不把缺少实时事实与缺少时钟混为一谈。
- 主题历史检索补充宠物、室友、朋友/同学/同事、家人、称呼、出行/考试和偏好，仍限定同用户与渠道、引用最多 10 条。没有检出证据不证明用户从没说过；最新用户纠正优先于旧叙述和旧助手回复。
- “别叫我某某”“就叫我某某”等直接称呼要求即时更新偏好，并废弃相反要求；最新称呼及最多三条停用称呼优先进入记忆上下文。后台迟到的旧称呼候选不能覆盖更新的明确要求。Web 会话标题不作为真实姓名提供给模型。
- 对话跟踪“只想吐槽”与“现在要建议”的切换，也允许用户明确重新邀请提问。关系规则只对有明确对象的负面表达扣分，不把用户对坏心情的吐槽当成针对角色的攻击，并排除明显否定或转述的好感表达。
- 日常历史提问优先按当前问题中的主体检索，移除常见问句、时间指代和功能词；没有匹配时回退到既有主题词。检索不只匹配旧叙述的否定词，以免召回“不吃”却漏掉“现在能吃微辣”的更新。检索仍为有限原话引用，不能把未检出当作从未说过。
- 用户明确“先不用推荐、先别分析”时，生成提示会收窄到接收分享或回答具体问题，并限制追加追问；明确的越界推荐会触发重写。图文同样执行这项文字要求检查，重写继续携带图片。后续明确要求挑选时可以给意见。
- schema 10 增加目标阶段、障碍、下一步、里程碑和数据包记录。初始化只在新数据库安装默认配置，已有数据库通过显式数据补全命令升级；精确识别旧启动产生的重复目标后归档，管理员自定义内容不覆盖。
- 当前角色的固定成长经历和关系网保存在 `character_versions.profile`，随版本一起发布。亲友是背景资料，不形成多个聊天角色；世界树只组合公开设定，不拼入用户私有记忆。
- 上下文先保留用户记忆预算，再按当前问题和必要指代读取公开世界、目标与亲友。成长经历按相关话题检索，语义复核承认已发布的背景证据，同时禁止把这些经历冒充当天活动或和用户的共同经历。
