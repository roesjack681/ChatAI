# 当前角色资料补全

本次只补全林知夏这一位聊天角色。父母、姐姐、室友、好友属于她的背景人物，不是新增可切换的聊天角色。完整已发布内容见 [当前角色配置](CURRENT_CHARACTER.md)。

| 内容 | 已配置 |
| --- | --- |
| 角色档案 | 55项，身份、教育、家庭、性格原因、习惯、偏好、情绪、社交、感情经历及知识边界等 |
| 人生经历 | 9段，从童年、初高中到大学当前阶段；每段包含年龄范围、事件、性格影响和相关人物 |
| 固定亲友 | 父亲林建平、母亲周敏、姐姐林晚晴、室友许棠、好友阿宁 |
| 关系网 | 8条，包含知夏与亲友、父母之间、姐姐与父母之间的关系、相处方式与边界 |
| 世界设定 | 32条有效事实，含城市、校园、6处生活场景及3个学校/社团背景 |
| 个人目标 | 3个，各自有阶段、障碍、下一步和5项里程碑 |
| 生活模板 | 13个，覆盖课程、自习、吃饭休息、兴趣、自由时间及睡前安排 |
| 提示词 | 11个模块，保留既有6个调好的模块，补充世界、目标、亲友、记忆与经历规则 |

后台“角色”页可以编辑具体经历和关系，保存草稿后发布生效。“生活”页的世界树可以查看完整结构，“亲友”页维护人物介绍，“目标”页显示阶段、障碍、下一步和进展。

成长证据、用户记忆、共同经历、已完成活动和新的人物互动需要实际依据。初始成长经历是管理员发布的角色背景，不会伪装成今天刚发生的事件或与用户已有的共同回忆；目标计划不计为执行成果。因此这些运行记录允许为空，不能为了消除空白捏造用户聊天或已经执行的行动。

已有数据库先执行 `npm run data:complete` 预览，再执行 `npm run data:complete -- --apply` 应用。应用前使用 SQLite `VACUUM INTO` 做一致性备份，在同一事务中比对用户、聊天、图片、记忆、用户关系、身份、提醒和私有事件的摘要，发生意外变化则全部回滚。管理员已有的非空角色字段及修改过的亲友、目标、模板保留。

修复了旧启动逻辑反复插入相同目标的问题。当前数据库原有45条未推进的默认摄影目标，仅保留一个作为正式目标，另外44条归档保留；再加入作品集和阅读目标。停用6条旧职业/重复生活模板，保留旧记录与已完成历史。重复启动不会重建已删资料或继续添加默认目标。

对话按问题及必要的上一个话题选择资料，支持“家里都有谁”“你俩闹过什么矛盾”“为什么选这个专业”等问法。先给用户私有记忆分配预算，再装入相关公开背景，避免世界资料增多后把旧称呼与喜好挤出上下文。背景亲友不读取真实用户的联系人，也不会跨用户共享聊天记忆。

测试结果与限制见 [测试说明](TESTING.md) 和 `data/*-quality-latest.json`；数据应用及备份位置见 `data/complete-data-applied.json`。
